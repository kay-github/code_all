# 金融看板云端更新

更新任务在 GitHub 托管运行器执行。通过采集、计算和验收后，运行器以项目白名单提交到 `main`。Vercel 从 `main` 部署，任务再对生产域名检查 HTTP 响应、构建号、业务日和发布文件哈希。台式机关机时调度照常运行。

| 任务 | 北京时间 | 发布条件 |
| --- | --- | --- |
| ETF 次日正式值 | 周一至周六 10:07、12:23 | 沪深两条指数日线确认业务日。深交所次日复核和现有发布闸门、独立验收均通过后，更新正式页、周期页、分段页及对应数据。 |
| ETF 盘中留档 | 工作日 14:17、14:39 | 连续竞价期间抓取一次同日新鲜快照，每日最多留一份。盘中快照和合格的 15 分钟基线随正式发布同步，页面内每 60 秒行情仍由浏览器直取。 |
| ETF 盘后初值 | 工作日 19:33、21:13 | 两条指数都提供当日完整日线后发布初值 JSON。正式版本通过后，在同一次发布里标记旧初值已被替代。 |
| 双龙回补 | 周一至周六 08:43、11:19 | 更新上一已完成交易日。保持 85% 同日净值覆盖率、披露分页与冲突检查及独立验收。 |
| 光通信跌幅榜 | 工作日 15:01、16:05 | 继续使用原有 `optical-daily.yml`。 |

GitHub 按表中的时刻调度，实际起跑受队列影响。第二个时点用于补跑。另有每半小时的兜底触发，按运行器实际启动的北京时间选择任务。基金 09:00–13:45、ETF 正式版 10:20–14:20、盘中留档 14:20–15:00、盘后初值 19:50 至当天结束。各任务仍采用表内的星期和发布条件。两条指数确认上一次已发业务日时跳过重复采集，覆盖不足或验收失败时保留上一版。定稿与盘后初值分别写入各自发布文件。

## 查看或补跑

在 [Market tracker updates](https://github.com/kay-github/code_all/actions/workflows/market-trackers.yml) 查看运行记录和验收附件。需要人工补跑时，在同页选择 **Run workflow**。

- `etf-final`、`etf-close`、`etf-intraday`、`fund` 使用正常入口和发布条件。正式区与基金支持选中 `rebuild` 重算已发布的同一业务日。
- `probe` 抽查公共行情、交易所份额、基金名录、净值和季报接口。
- `verify` 只读核对当前仓库回执与线上页面和数据，适用于推送后生产核对超时。
- ETF 的交易所份额历史和盘中快照检查点位于 `apps/national-team-etf/cloud-state/`。每次采集的验证及溯源附件保留 14 天。本机已有研究批次继续留在原目录。

GitHub Actions 使用运行器内置的仓库令牌提交产物。Vercel 沿用仓库既有集成。
