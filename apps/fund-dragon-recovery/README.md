# 光模块双龙公募回补跟踪 v3

目标是尽早发现公募对新易盛（300502）、中际旭创（300308）的收益关联变化，并核对可确认的披露持仓。**收益模型不能还原实时实际仓位，不能确认买入、未卖或清仓。**

线上入口：[双龙跟踪](https://1.688680.xyz/jjhc)。业务日、采集时间、样本覆盖和构建号均在页面标明。手动更新，不创建定时任务。

## 更新与验收

Python 3.11+、NumPy、Node.js；发布还需当前仓库 Git 和已登录的 Vercel CLI。安装依赖：`python -m pip install -r requirements.txt`。

从本目录执行：

```powershell
python -X utf8 update.py                    # 完整采集 → 初算 → 优先候选个基对照 → 复算 → 独立验收
python -X utf8 update.py --analyze-only     # 仅复算一个已有原始批次，不混用旧行情与新净值
python -X utf8 update.py --analyze-only --review  # 同时补抓优先候选的个基资料
python -X utf8 update.py --validate-only    # 重新验收已有构建
python -X utf8 publish.py                  # 准备已验收发布文件，运行站点测试
python -X utf8 publish.py --deploy         # 白名单提交推送，等待并核对线上
```

也可一步 `python -X utf8 update.py --deploy`。**发布只接受当前代码、配置、原始批次和验收相互匹配的结果。** 最近已完成交易日由两只宽基指数的同源日线共同确认；15:15 前不采纳当天盘中日线。收盘后净值未齐时保留缺失状态；覆盖不足会阻止发布，稍后手动重跑。

研究历史数据可用 `--end YYYY-MM-DD`；不要将历史研究构建发布为当前数据。历史模型使用当前回溯数据和当前观察池，不冒充当时可知的实时样本外结果。新季度报告未公布或接口不可用时，采集失败会显式停止，保留已有线上页面；修复来源或等待披露后重新运行，不自动沿用旧数据装作刷新成功。

## 一条数据链路

1. 东方财富基金目录与最近两个已结束季度的目标股持有人反查，加上原始119条种子，不设高权重门槛；目录类型区分主动、指数增强、公募被动指数及其他类别。指数增强单列观察，不据净值确认主动回补。
2. 净值保存公布收益、单位净值、分红说明和实际净值日期；按相邻交易日对齐。缺失收益不填0，缺上一日不把跨日变动记作单日，未说明的明显净值/收益矛盾隔离。后端收费代码没有独立净值时保留未知。
3. 腾讯同源前复权行情；宽窄产业篮子剔除双龙。近80日使用固定完整成分，覆盖不足不计算；缺复权系列不拿未复权替代。北交所单独使用 `bj` 前缀。
4. `v3_engine.py` 统一计算收益暴露、区间、窗口变化、辨识度、留出表现和多重比较修正；个基其他已披露重仓股作为额外混淆对照。
5. 一份 `analysis.json.gz` 同时生成三份本地兼容视图、线上 HTML、公开 JSON 和逐组 CSV。旧“坚守名单”名称仅保留文件入口，已取消不可靠的未卖/清仓和规模推算。

`data/v3/raw/<run>/` 保存原始响应、URL、抓取时间、哈希和解析快照；个基补充资料在独立子目录，不能覆盖父批次。`builds/<build>/` 保存配置、计算指纹、分析、CSV、视图、验收和上线核对记录；`observations.jsonl` 按日期、组ID和构建号追加研究观察。一天可有多个修订批次，不应把它们计为多个交易日；按同日最终已验收构建取数，保留此前版本供比较。

## 判断边界

- 已披露持仓：报告期、股数、市值与净资产占比分开保存。未列前十大或反查未见不是零持仓，旧季度不能冒充当前季度。
- 弱线索：点估计变化、模型分歧、负向关联缓和分别展示；不因门槛没过就删除观察组。
- 较强候选：市场暴露自由估计，20/40/60日模型；前后20日不重叠。需正向变化区间、宽窄一致、足够辨识度、解释力、BY修正、留出表现及个基对照共同通过。
- 个基对照未通过会降级。资料不足与检验不支持不同；通过仍不证明真实买卖。原始定报仅样本核验，不夸大全池第一手核验范围。
- 没有真实最新持仓真值，不能给出市场识别准确率、召回率。当前阈值是研究规则，禁止用历史峰值循环校准“满仓”。模型永不自动停止长期追踪。

方法细节见 [研究方法](docs/研究方法.md)，本次修复证据与验收结果见 [审查记录](docs/审查记录_20261114.md)，持续完善见 [经验与后续核验](docs/经验与后续核验.md)。

## 代码与发布安全

旧脚本均改为统一入口的兼容包装；`fix_weights.py`、`patch_pool.py`、`probe_scale.py` 的人工补丁/粗略规模逻辑停用。旧根目录缓存只用于审计，v3 不读取它们。

本地原始资料与私有路径不发布到仓库。发布源码位于 `apps/fund-dragon-recovery/`，页面和公开数据位于 `tools/fund-dragon-recovery/`。只提交项目白名单；保留其他暂存和未提交改动，不自动 stash/rebase，不把无关本地提交一起推送。文本哈希统一归一化 CRLF→LF，避免 Windows Git 换行导致发布误报。

可用环境变量：`FUND_TRACK_DATA`（本机批次数据）、`FUND_TRACK_REPORTS`（本地视图）、`FUND_TRACK_REPO`（工具站仓库）。从仓库源码目录执行时，默认结果写入本目录 `output/`，不依赖原机器绝对路径。
